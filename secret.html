Check it

Open the link yourself in a private window and decrypt it before you send anything. If it does not work for you, it will not work for them, and the message only exists inside that link.

How it works

Your password is stretched into a 256-bit key with PBKDF2-HMAC-SHA256 (600,000 iterations, random 16-byte salt) and the message is encrypted with AES-256-GCM using a random 12-byte IV. All of that happens in this page, using the browser's own Web Crypto — there is no library to trust and nothing is fetched.

The result is placed after the # in the link. Browsers never transmit that part of a URL to a server, which is what makes this work: the ciphertext never reaches Netlify, never lands in a log, and is never stored. This page is served with connect-src 'none', so the browser will refuse to let it make any network request at all. You can confirm that in your developer tools, and you should not have to take my word for it.

What this does not do

  • It cannot expire, and it cannot be revoked. There is no server, so there is nothing to delete. The link works for as long as it exists, for anyone holding it and the password.
  • It will not tell you it was read. Nothing reports back. Nothing can.
  • It does not hide who is talking to whom. The email itself, its subject, and the fact you sent it are all as visible as any other email.
  • It is only as good as the password. A guessable password with the link in hand is a guessable message. This is why the generated one is the default.
  • The link goes in the recipient's browser history and in whatever backups their mail client keeps. That is the copy most likely to outlive your intentions.

For anything where those limits actually matter — where you need it to expire, or to be revocable, or to survive a subpoena thoughtfully — this is the wrong tool and a properly keyed system is the right one. Ask me and I will tell you which.

This browser can't do it.

The page needs Web Crypto, which every current version of Chrome, Edge, Firefox, Safari and Opera has, but which is only available over HTTPS. If you are looking at this over a plain http:// address, that is the reason.
